# 含硫 N 体模型批量流程：Notebook 优先的开发设计

> 归档说明（2026-10-17）：本文保留主工作区设计背景，文中 `notebooks/` 路径属于被 Git 忽略的本地研究区。可版本化的备份工作流位于 `kong_2027_backup/`，其路径隔离与组成口径将在后续独立提交中记录；本文不表示这些代码已包含在当前文档提交中。

## 设计目标与现状

目标是在**一个主 notebook 中看清并调整各子模块参数**，一次运行多个 N 体模型，同时保留每一步实际使用的参数和执行结果，供人工检查。参照 `notebooks/Fe_enrich_v3/script.ipynb` 的可读执行计划和各子模块首个参数单元；保留当前含硫流程已经实现的独立输出、失败隔离、产物验证和求解诊断。

本文件记录当前 notebook 优先的批量流程设计。主 notebook 已列出完整参数；A–E 子模块首个代码单元已标记 `parameters`；执行器保存参数化与执行后的副本。`notebooks/` 是试验区，保持现有 Git 忽略规则，实测通过后再整理进正式项目。

按模型覆盖最新成功结果的输出实现见 [按模型保留最新结果的输出设计](sulfur_batch_latest_results_design.md)。本文着重记录参数与阶段契约；输出、日志、覆盖和失败恢复以该文件为准。

## 主 notebook：唯一的日常调参入口

主入口继续使用 `notebooks/work_flow_S_batch/run_batch.ipynb`，依次设置：

1. **模型与运行范围**：`MODEL_LIST`、数据根目录、输出根目录、运行起止阶段；默认按 A_01 → B_01 → B_02 → C_01 → C_02 → D_01 → E_01 顺序执行。
2. **共用参数**：例如气体盘终止时刻，以及 C_01/C_02 必须一致的巨碰撞判定阈值。共用值在主 notebook 只定义一次，在执行计划中展开给相关模块。
3. **显式 `EXECUTION_PLAN`**：每项直接写出模块文件名、`enabled`、该模块全部实际参数及简短注释。无论参数是否偏离默认值，主 notebook 都要显示它；不得只显示覆盖值。默认的科学数值不得仅藏在执行器中。
4. **计划预览**：按模型和阶段打印最终参数、输入文件和输出目录。执行之前可发现拼写、路径或参数不一致。
5. **正式执行单元**：运行已预览的计划。计划预览与正式执行分成两个单元；正式执行单元不再依赖不明显的 `RUN_BATCH` 开关。

例如，C 阶段在主 notebook 中应能直接看见 `C_01` 的小碰撞压力比例、质量阈值、撞击质量比和冷却时间，以及 `C_02` 独立的局部熔融压力比例。可以用 `C_COMMON` 定义两模块共用的判定参数，但计划预览与保存的副本必须显示**展开后的完整数值**。模型 ID 与输入/输出路径也要在预览和副本中成为明确值。

普通使用先采用一套完整参数配置与 `MODEL_LIST`；需要比较参数情景时，再为整套配置命名并复制/修改该方案。不要让 `baseline` 加少量覆盖值成为唯一的参数编辑方式。

## 子模块：第一个代码单元就是参数契约

每个 A–E notebook 的**第一个代码单元**统一标记为 `parameters`，只包含该模块的显式参数赋值、单位/物理意义注释和必要的参数范围说明。第二个单元才导入库、解析路径和执行计算。直接打开子模块运行时，使用首单元的默认值；批量运行时，执行器复制 notebook，仅替换该首单元为主 notebook 展开后的赋值，不修改原件，不通过隐藏环境变量传递科学参数，也不靠正则搜索任意单元中的同名赋值。

| 模块 | 首单元需要显式列出的参数 | 注释重点 |
| --- | --- | --- |
| A_01 陨石初始成分 | EF、EC、OC、CI 的原始 S 重量值；EF 富集/贫化系数；输入/输出路径 | S 原始值的来源与可修订性；其他固定常数与可调参数分开 |
| B_01 胚胎初始成分 | 模型 ID、N 体目录、初始及气体盘终止时刻、陨石类型轨道分区、A_01 成分表、输出路径 | 区分计算参数与只影响画图的胚胎显示阈值；保留既有分区判定顺序 |
| B_02 吸积历史 | 模型 ID、N 体目录、同一气体盘终止时刻、最终行星质量阈值（当前 `0.01 M⊕`）、输出路径 | 行星按最终轨道半长轴排序；阈值决定哪些对象进入后续计算 |
| C_01 小碰撞与全局基线 | 小碰撞压力比例、巨碰撞质量阈值、撞击质量比范围、全局岩浆洋冷却时长、输入/输出路径 | 先计算 `small/global`，保留全局熔融性质 |
| C_02 巨碰撞更新 | 从 C_01 继承的质量/比例判定值、独立的局部熔融压力比例、输入/输出路径 | 将符合条件的源事件改为 `partial`；默认值先保持当前数值结果不变 |
| D_01 含硫分异 | 根搜索模式、各事件核再平衡比例、目标地幔再平衡因子、氧 KD 精确/近似残差阈值、质量及守恒容差、输入/输出路径 | 明示当前三层求解顺序；科学策略的变动须单独命名情景 |
| E_01 结果比较 | 输入/输出路径、比较参考值、坐标默认范围、图尺寸和导出开关 | Earth/Mars 参考值及来源单列记录；默认不当作普通可调拟合参数 |

这张表是接口清单，不表示当前全部参数已经集中在首单元。迁移时要检查是否还有散落的计算常数；确属可调项的移到首单元，纯物理常数或内部数值实现参数则明确标注为固定项。所有阶段的参数名、单位和默认值应与主 notebook 一一对应，未知参数报错，缺失参数不能静默使用执行器的隐藏默认值。

C_01 的 `05_small_global_impact_events_S.xlsx` 是中间产物，C_02 的 `05_impact_events_S.xlsx` 才供 D_01 使用。C_01 先计算全局属性，再由 C_02 更新 `partial`，不能因拆成两个 notebook 改变这一计算顺序。B_01 必须逐模型运行；A_01 只在初始成分和代码完全一致时才可共享。

## 每个模型保留最新成功结果

主 notebook 中的 `OUTPUT_ROOT` 指定全部结果根目录。每次批次从 A_01 重新计算，先在 `.staging/` 完成与验证，再把成功模型的完整结果提交到 `models/<model_id>/`；同模型旧结果被整体替换，其他模型不受影响。这里保存该次参数快照、通过验证的表、阶段工作区，以及参数化和执行 notebook。失败模型不覆盖旧结果。

`latest_run/` 只保存最近一次批次的日志、状态和汇总；下次运行覆盖。正式目录的完整结构、路径映射与中断恢复见[输出设计](sulfur_batch_latest_results_design.md)。原始 A–E notebook 与 N 体数据保持只读。

## 执行与验证

执行器只处理路径、参数单元替换、notebook 执行、产物验证和日志；**不定义科学参数默认值，也不改变物理方程**。首版逐模型顺序运行。缺少必需 notebook、输入文件或上游产物时立即报错；某模型某阶段失败，停止该模型下游并继续其余模型。不得从固定 `Tables` 路径读取上一次模型的残留数据。

每阶段执行前核对参数名、类型、范围、共用参数一致性及输入文件；执行后检查输出存在、可读取、关键列齐全、事件时间与行星轨道顺序正确、S = S_sil + S_met。D_01 还须核查质量/元素守恒，并保存 `accepted_approximate`、`oxygen_converged`、氧 KD 残差和求解策略等逐事件诊断。Notebook 运行成功只说明程序完成，不等于每个事件都有精确物理根。

每次正式运行从 A_01 开始重新执行全部启用阶段，不读取或写入阶段缓存。各阶段先在隔离目录运行和验证，模型的全部启用阶段成功后才整体提交；失败不得留下可被误读为本次结果的旧文件。

## 跨模型与跨方案汇总

每次运行至少生成批次状态表，列出所有模型、阶段状态、失败原因及运行目录。只对已通过验证的结果生成行星汇总：质量、最终轨道半长轴、Mg#、CMF、地幔/地核 S；同时保存撞击类型统计、D_01 精确/近似解计数、近似解比例与残差分布。逐事件表包含 `attempt_id`、方案、模型、行星、事件序号、时间、温压和求解策略，以支持日后系统研究无根事件的出现比例和参数范围。失败模型必须在批次状态表中可见，不能悄悄从统计样本中消失。

## 实施顺序与验收

1. 重排七个子模块：把完整参数契约放到首个代码单元，保留单独运行的默认值；统一 C_01/C_02 共用和各自参数。
2. 重做主 notebook：显式 `EXECUTION_PLAN`、完整参数和单位注释、模型循环、展开后的计划预览；把隐藏在 `batch_core.py` 的科学默认值移回可见的 notebook 参数单元。
3. 重做执行器：按标记替换首单元，默认保存参数化副本和执行副本，隔离输出并验证产物；保留失败隔离。
4. 用一个已人工验证的模型逐表对照 A–E；再运行两个模型、一个参数变体，确认目录隔离、参数快照、失败处理与汇总诊断正确。

验收时，应能只打开主 notebook 就找到所有子模块的实际可调参数；只打开任一保存的执行副本，就能确认这次使用的模型、输入路径和完整参数。批量结果应与相同参数下的人工流程一致。代码实现后仍需用更多已人工验证的 N 体模型完成逐表和跨模型验收。
