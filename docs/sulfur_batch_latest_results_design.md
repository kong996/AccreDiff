# 含硫批量流程：按模型保留最新结果的输出设计

> 归档说明（2026-10-17）：本文保留主工作区设计背景，文中 `notebooks/` 路径属于被 Git 忽略的本地研究区。可版本化的备份工作流位于 `kong_2027_backup/`，其路径隔离与组成口径将在后续独立提交中记录；本文不表示这些代码已包含在当前文档提交中。

## 目标与边界

本文件记录已实施的输出布局；旧的 `runs/<run_id>/...` 目录仍作为历史数据保留。目标是在频繁调整参数时控制文件数量：每次仍从 A_01 重新执行全部启用阶段，但同一模型只保留最近一次**成功且通过验证**的结果；不同模型的结果互不覆盖。本次批处理的日志、状态和汇总只保留一套，下次正式运行覆盖。`notebooks/` 继续作为被 Git 忽略的试验区；此改造不改变 A–E 的科学计算、参数首单元、求解策略和产物验证规则。

“最新结果”和“最近一次尝试”必须区分：计算失败时，磁盘上可能仍有该模型上一次成功的结果，但它不能被标记为本次参数的结果。

## 指定输出目录与文件布局

主 notebook 中的 `OUTPUT_ROOT` 是唯一需要指定的输出根目录。以 `OUTPUT_ROOT = notebooks/work_flow_S_batch/results` 为例：

```text
OUTPUT_ROOT/
  models/
    <model_id>/
      parameters.json                 # 这套表对应的完整参数和源 N 体路径
      manifest.json                   # 最近一次成功结果的阶段状态与产物校验
      tables/                         # A–E 经验证的 CSV、XLSX、JSON
      stage_workspaces/              # 本次各阶段的输入/输出检查副本
      parameterized_notebooks/        # 与当前表对应的参数化副本
      executed_notebooks/             # 与当前表对应的执行副本
  latest_run/
    batch_status.csv                  # 本次选中模型的成功/失败状态
    attempt.json                      # 本次模型列表、参数方案、开始/结束时间
    logs/_shared/A_01.log             # 本次共用 A_01 的日志
    logs/<model_id>/<stage>.log       # 本次运行日志；下次运行整体替换
    planets.csv                       # 仅本次成功完成 E_01 的模型
    solver_events.csv                 # 仅本次成功模型的逐事件诊断
    solver_summary.csv
    impact_counts.csv
  .staging/                            # 运行中的隔离工作区；完成后清理
```

`models/<model_id>/` 是稳定地址，不含 `run_id` 或 `scenario_id`。同一模型再次成功运行后，用新目录替换该模型旧目录；其他模型目录保持原样。`scenario_id` 继续作为 `parameters.json` 中的实验标签，但**不构成保留旧参数结果的路径**。模型 ID 必须是安全且唯一的目录名；若两个数据根目录使用相同 ID，调用者应先改名或选择不同的 `OUTPUT_ROOT`，避免误覆盖。

`latest_run/` 属于最近一次**批处理尝试**，而非历史档案。运行开始时先清理或重建其内容；若批次只选中一个模型，此处也只保留这个模型的日志。下一次选择不同模型时，上次模型的日志会消失，但它在 `models/` 下的成功数据仍在。临时目录中的计算日志必须在清理前复制到 `latest_run/logs/`。不再创建永久性的 `runs/<run_id>/` 目录；可以在 `attempt.json` 中保留时间戳形式的 `attempt_id`，仅供诊断和表内溯源。

## 一次运行的提交规则

1. 主 notebook 校验并预览所有参数、模型 ID、输入路径和最终 `models/<model_id>/` 地址。预览明确提示同模型成功后将覆盖旧结果；正式执行单元仍直接运行，无额外确认开关。
2. 在 `OUTPUT_ROOT/.staging/<attempt_id>/` 建立本次独立工作区。A_01 可以在同一批次计算一次并复制给各模型；B_01 起逐模型执行。阶段从此工作区读取本次上游表，绝不能回读 `models/<model_id>/tables/` 中的旧表。
3. 每阶段继续生成参数化和执行 notebook，验证表结构、行星轨道顺序、S 相守恒及 D_01 求解诊断。阶段失败时停止该模型下游，并继续其他模型。
4. **只有该模型全部启用阶段成功且所需产物通过验证**，才把工作区中的 `tables/`、`stage_workspaces/`、参数快照、notebook 副本和 manifest 一起提交到 `models/<model_id>/`。提交以目录为单位，不能逐表覆盖，以免新旧参数结果混合。提交前将保存副本首单元中的暂存路径映射到最终模型目录，并在 notebook metadata/manifest 中记录原执行时使用的暂存路径；科学参数值与已执行输出不得改动。提交后检查副本所指文件在新目录中确实存在。
5. 提交时先把旧模型目录临时改名，再把完整的新目录移到固定地址；提交完成后清理旧目录。整个过程在现有输出锁保护下执行。若提交中断，启动时应识别残留的临时旧目录并恢复或报告，不能悄悄把不完整目录当成成功结果。
6. 不论成功或失败，都将本次日志和状态写入 `latest_run/`；全部模型处理完成后清理 `.staging/<attempt_id>/`。批次失败时，已有模型的旧成功结果保持不变。

如果运行范围停在 A_01、B_02 等中间阶段，它只产生**部分流程结果**：manifest 必须写明 `last_stage`，不能把缺少 D/E 的结果标成完整 A–E。下次同模型完整运行成功后，再整体替换。若要保证 `models/` 永远只存完整 A–E，可进一步限制正式运行必须到 E_01；首版沿用当前可截断的工作方式，并显式记录完成阶段。

## 状态、汇总与可追溯性

`models/<model_id>/parameters.json` 和表始终属于同一次成功提交；失败尝试不得更新这份参数快照。`latest_run/batch_status.csv` 列出本次选中的**所有**模型、目标阶段、状态、失败阶段、失败原因、固定结果目录，以及该目录是否仍是较早的成功结果。失败模型即使磁盘上有旧表，也不进入本次行星和求解器统计。

跨模型汇总文件只覆盖最近一次批处理，且只汇总本次成功并完成相关阶段的模型。它们不自动扫描 `models/` 下所有旧模型，因为那些模型可能使用不同的参数或不同的 N 体输入。若日后需要跨历史模型的统一比较，应另建读取并检查参数一致性的汇总模块，不在本次输出改造中混合样本。

逐事件表继续保留方案、模型、行星、事件、时间、温压、`solution_strategy`、`accepted_approximate` 和氧 KD 残差。原有 `run_id` 字段改为本次 `attempt_id`（或保留列名但明示它只是本次尝试标识）；在模型目录中保留最近一次成功提交的标识与时间。输出日志和表可以被覆盖，因此如需长期引用某组科学结果，使用者应自行复制或导出，而不是把该目录当成历史版本库。

## 与现有代码的改造点

- `run_batch.ipynb`：保留完整 `EXECUTION_PLAN` 和 `OUTPUT_ROOT`；预览固定模型目录及覆盖语义，去掉按 `run_id` 展示永久产物路径的说明。
- `batch_core.py`：改造 `execute()` 的目录分配、A_01 共用工作区、逐模型提交和 `collect_summary()`；`resolved_parameters()` 执行时指向隔离工作区，提交时把保留副本的路径改写为稳定的模型目录并记录原路径。保留输出锁、失败隔离和阶段验证。
- `README.md` 与主流程设计文档：更新目录树、覆盖规则、失败语义和批次汇总含义。
- 不修改七个 A–E notebook 的计算方程；只有路径契约确有必要时才调整参数解析。

已有 `runs/<run_id>/...` 历史目录**不自动删除或迁移**。新布局只影响改造完成后的运行。旧目录清理由使用者另外决定；避免在首次启用新布局时误删此前的研究记录。

## 验收场景

1. 同一模型用两组参数连续运行：`models/<model_id>/` 地址不变，第二次成功后表、参数快照和 notebook 全部属于第二组；`latest_run/logs/` 不保留第一次日志。
2. 先运行模型 A，再运行模型 B：两个模型的最新成功数据都存在；`latest_run/` 只显示 B 那次的日志和状态。
3. 同批运行 A、B，其中 B 在 D_01 失败：A 的新结果提交；B 原有完整结果不变；本次状态明确标记 B 失败与旧结果的存在，汇总不纳入 B。
4. 在验证或提交阶段制造中断：不会出现混合新旧阶段表的模型目录；恢复逻辑能识别并处理残留临时目录。
5. 核对单模型同参数的旧流程与新布局：数值表及求解诊断一致，变化仅限路径、覆盖和日志保留方式。
